# Свой сервер KMP Music

Сервер хранит вашу библиотеку — плейлисты, избранное и историю — и синхронизирует её между
компьютером и телефоном. Музыку он не хранит и не передаёт: каждое устройство берёт её с YouTube
само, поэтому сервер лёгкий (~150 МБ памяти) и подойдёт даже домашний ПК или Raspberry Pi.

Ниже — установка на домашний компьютер с доступом из интернета через **Cloudflare Tunnel**:
порты в роутере открывать не нужно, HTTPS-сертификат выдаёт Cloudflare.

## Что понадобится

- Компьютер, который почти всегда включён (Windows, Linux или macOS).
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/macOS) или Docker Engine (Linux).
- Домен, подключённый к Cloudflare (бесплатный тариф). Если домена нет, его можно купить
  прямо в Cloudflare → Domain Registration.

## 1. Туннель в Cloudflare

1. Откройте [панель Cloudflare](https://dash.cloudflare.com) → **Zero Trust** → **Networks** → **Tunnels**.
2. **Create a tunnel** → тип **Cloudflared** → придумайте название (например, `kmp-music`).
3. На шаге установки коннектора Cloudflare покажет команду вида
   `cloudflared service install eyJhIjoi…`. Скопируйте длинную строку после `install` — это **токен туннеля**.
   Саму команду выполнять не нужно: коннектор запустится в Docker.
4. На вкладке **Public Hostname** добавьте адрес:
   - **Subdomain**: например, `music`
   - **Domain**: ваш домен
   - **Service**: `HTTP` и `server:8080`

Сервер будет доступен по адресу вида `https://music.ваш-домен.ru`.

## 2. Запуск сервера

1. Создайте папку, например `kmp-music-server`, и положите в неё два файла из папки
   [`deploy`](../deploy) этого репозитория: `docker-compose.yml` и `.env.example`.
2. Переименуйте `.env.example` в `.env`, раскомментируйте строки туннеля и вставьте токен:
   ```
   COMPOSE_PROFILES=tunnel
   TUNNEL_TOKEN=eyJhIjoi…
   ```
   Без этих строк запустится только сервер, доступный с этого компьютера по `http://localhost:8080`, —
   так удобно сначала проверить, что всё работает.
3. В этой папке выполните:
   ```bash
   docker compose up -d
   ```
4. Проверьте, что всё работает: откройте `https://music.ваш-домен.ru/health` — должно быть `ok`.

На Windows включите в Docker Desktop **Settings → General → Start Docker Desktop when you sign in**,
чтобы сервер поднимался сам после перезагрузки.

## 3. Первый вход

1. В приложении KMP Music откройте вход в аккаунт и укажите адрес сервера `https://music.ваш-домен.ru`.
2. Сервер пустой, поэтому приложение предложит создать аккаунт — **первый аккаунт становится администратором**.
3. После этого регистрация закрыта: новые аккаунты — только по приглашениям.

## Пригласить близких

Администратор создаёт код-приглашение (действует 7 дней, одноразовый) и отправляет его вместе с
адресом сервера. Человек вводит адрес, код, придумывает имя и пароль — и получает свою отдельную
библиотеку: аккаунты друг друга не видят.

## Обслуживание

| Задача | Команда (в папке сервера) |
|---|---|
| Обновить до новой версии | `docker compose pull && docker compose up -d` |
| Посмотреть журнал | `docker compose logs -f server` |
| Остановить | `docker compose down` |
| Резервная копия | скопируйте папку `data` (лучше при остановленном сервере) |

В папке `data` лежат база `kmp-music.db` и секрет `jwt-secret`, которым подписываются сессии.
Если удалить секрет, всем придётся войти заново; если удалить базу — пропадут аккаунты и библиотеки.

## Безопасность

- Пароли хранятся только в виде хешей bcrypt; вход и регистрация ограничены 10 попытками в минуту с адреса.
- Сессия на устройстве держится 60 дней с последнего использования; смена пароля завершает все остальные сессии.
- Наружу открыт только туннель: порт 8080 доступен лишь с самого компьютера.
- Трафик между устройством и Cloudflare шифруется, но Cloudflare, как и любой обратный прокси,
  технически видит содержимое запросов (то есть вашу библиотеку). Если это неприемлемо, вместо
  туннеля используйте [Tailscale](https://tailscale.com) — тогда в `docker-compose.yml` удалите сервис `tunnel`.

## Для разработчиков

- Образ собирается GitHub Actions при каждом изменении сервера в `main` и публикуется как
  `ghcr.io/jbly312/kmp-music-server`. Новый пакет в GHCR по умолчанию приватный — сделайте его
  публичным в настройках пакета, чтобы `docker compose pull` работал без входа.
- Локальный запуск без Docker: `./gradlew :server:run` (данные — в `server/data`).
- Запустить из исходников, не дожидаясь образа в GHCR (из папки `deploy`):
  `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build`
- Протокол API описан в [`sync-protocol`](../sync-protocol/src/commonMain/kotlin/org/example/videoplayerkmp/sync/Protocol.kt).
