# Свой сервер KMP Music

Сервер хранит вашу библиотеку — плейлисты, избранное и историю — и синхронизирует её между
компьютером и телефоном. Музыку он не хранит и не передаёт: каждое устройство берёт её с YouTube
само, поэтому сервер лёгкий (~150 МБ памяти) и подойдёт даже домашний ПК или Raspberry Pi.

Чтобы сервер был доступен с телефона, его нужно открыть в интернет. Порты в роутере открывать не нужно —
есть два способа:

| | Tailscale Funnel (рекомендуется) | Cloudflare Tunnel |
|---|---|---|
| Свой домен | не нужен — адрес вида `https://kmp-music.tailXXXX.ts.net` | нужен, подключённый к Cloudflare |
| Кто видит трафик | никто: HTTPS расшифровывается на вашем компьютере | Cloudflare (расшифровывает на своей стороне) |
| Телефону | ничего не нужно, работает и с включённым VPN | ничего не нужно |
| Цена | бесплатно | бесплатно (+ домен) |

## Что понадобится

- Компьютер, который почти всегда включён (Windows, Linux или macOS).
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/macOS) или Docker Engine (Linux).
- Аккаунт [Tailscale](https://tailscale.com) (бесплатный) — или домен в Cloudflare для второго способа.

## 1. Подготовка Tailscale

1. Зарегистрируйтесь на [tailscale.com](https://tailscale.com).
2. В [панели Tailscale](https://login.tailscale.com/admin/dns) на вкладке **DNS** включите **MagicDNS**
   и **HTTPS Certificates**.
3. На вкладке **Settings → Keys** нажмите **Generate auth key**. Ключ должен быть **не** «Ephemeral»
   и **без тегов** — иначе Funnel может быть запрещён политикой доступа. Скопируйте ключ (`tskey-auth-…`).

Имя устройства и сети попадают в публичный журнал HTTPS-сертификатов — не используйте в имени личные данные.
По умолчанию устройство называется `kmp-music`.

## 2. Запуск сервера

1. Создайте папку, например `kmp-music-server`, и положите в неё из папки [`deploy`](../deploy) этого
   репозитория: `docker-compose.yml`, `docker-compose.tailscale.yml`, `.env.example` и папку
   `tailscale/config` (в ней `serve.json` — настройка Funnel).
2. Переименуйте `.env.example` в `.env` и вставьте ключ:
   ```
   TS_AUTHKEY=tskey-auth-…
   ```
3. В этой папке выполните:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.tailscale.yml up -d
   ```
4. Разрешите Funnel в своей сети Tailscale (один раз). Выполните:
   ```bash
   docker exec kmp-music-tailscale tailscale funnel --bg --yes 8080
   ```
   Если Funnel ещё не разрешён, команда напечатает ссылку `https://login.tailscale.com/f/funnel?node=…` —
   откройте её, подтвердите и выполните команду ещё раз. Без этого шага сервер молча не публикуется:
   `tailscale funnel status` показывает «Funnel on», но адрес из интернета не открывается.
5. В выводе будет адрес вида `https://kmp-music.tailXXXX.ts.net`. Откройте `…/health` — должно быть `ok`.
   Публичная DNS-запись появляется не сразу: если адрес не открывается, подождите до 10 минут.

На Windows включите в Docker Desktop **Settings → General → Start Docker Desktop when you sign in**,
чтобы сервер поднимался сам после перезагрузки.

Срок действия ключа (до 90 дней) важен только для первого входа: потом устройство остаётся в сети,
пока жива папка `tailscale/state`. Не удаляйте её — иначе появится новое устройство с другим адресом.

## 3. Первый вход

1. В приложении KMP Music откройте вход в аккаунт и укажите адрес сервера.
2. Сервер пустой, поэтому приложение предложит создать аккаунт — **первый аккаунт становится администратором**.
3. После этого регистрация закрыта: новые аккаунты — только по приглашениям.

## Пригласить близких

Администратор создаёт код-приглашение (действует 7 дней, одноразовый) и отправляет его вместе с
адресом сервера. Человек вводит адрес, код, придумывает имя и пароль — и получает свою отдельную
библиотеку: аккаунты друг друга не видят. Ставить Tailscale близким не нужно.

## Обслуживание

Команды выполняются в папке сервера. Чтобы не писать `-f …` каждый раз, задайте в `.env`
`COMPOSE_FILE=docker-compose.yml;docker-compose.tailscale.yml` (на Linux и macOS — через `:`).

| Задача | Команда |
|---|---|
| Обновить до новой версии | `docker compose pull && docker compose up -d` |
| Посмотреть журнал | `docker compose logs -f server` |
| Остановить | `docker compose down` |
| Резервная копия | скопируйте папки `data` и `tailscale/state` (лучше при остановленном сервере) |

В папке `data` лежат база `kmp-music.db` и секрет `jwt-secret`, которым подписываются сессии.
Если удалить секрет, всем придётся войти заново; если удалить базу — пропадут аккаунты и библиотеки.

## Безопасность

- Пароли хранятся только в виде хешей bcrypt; вход и регистрация ограничены 10 попытками в минуту с адреса.
- Сессия на устройстве держится 60 дней с последнего использования; смена пароля завершает все остальные сессии.
- Наружу открыт только Funnel (или туннель): порт 8080 доступен лишь с самого компьютера.
- Серверы Tailscale Funnel пересылают зашифрованный трафик и не могут его прочитать — HTTPS
  расшифровывается контейнером Tailscale на вашем компьютере.

## Другой способ: Cloudflare Tunnel (нужен свой домен)

1. Домен должен быть подключён к Cloudflare (**Domains → Add domain** или **Buy domain**).
2. [Панель Cloudflare](https://dash.cloudflare.com) → **Networking → Tunnels → Create Tunnel**, тип окружения **Docker**.
   Из показанной команды скопируйте строку после `--token` — сама команда не нужна.
3. Туннель → **Routes → Add route → Published application**: **Hostname** — поддомен и ваш домен,
   **Service URL** — `http://server:8080` (именно `server`: коннектор обращается к серверу по имени сервиса).
4. В `.env`:
   ```
   COMPOSE_PROFILES=tunnel
   TUNNEL_TOKEN=eyJhIjoi…
   ```
5. Запуск — только основной файл: `docker compose up -d`.

Если туннель не подключается с ошибкой про `_v2-origintunneld._tcp.argotunnel.com`, ваша сеть не пропускает
нужную ему SRV-запись — укажите в `.env` DNS роутера: `TUNNEL_DNS=192.168.1.1`.

Cloudflare, как обратный прокси, технически видит содержимое запросов (то есть вашу библиотеку).

## Для разработчиков

- Образ собирается GitHub Actions при каждом изменении сервера в `main` и публикуется как
  `ghcr.io/jbly312/kmp-music-server`. Новый пакет в GHCR по умолчанию приватный — сделайте его
  публичным в настройках пакета, чтобы `docker compose pull` работал без входа.
- Локальный запуск без Docker: `./gradlew :server:run` (данные — в `server/data`).
- Запустить из исходников, не дожидаясь образа в GHCR: добавьте `-f docker-compose.build.yml`
  к командам выше и флаг `--build`.
- Протокол API описан в [`sync-protocol`](../sync-protocol/src/commonMain/kotlin/org/example/videoplayerkmp/sync/Protocol.kt).
